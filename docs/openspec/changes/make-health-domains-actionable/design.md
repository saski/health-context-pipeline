## Navigation policy

Resolve navigation by Health Connect data-origin package. Use a documented and
verified category deep link when one exists; otherwise use the package's normal
launcher intent. If more than one source contributes, show a chooser rather
than guessing.

## UI direction

The primary surface should contain automation health and the six domain cards.
Development explanations and manual recovery actions remain accessible but are
progressively disclosed instead of occupying the main flow.

Before changing the layout, inventory every visible element against the
everyday job: understand today's coverage, open a useful source, and recover a
failed automatic export. Remove elements with no current user job, merge
duplicated status, and move infrequent setup or diagnostic actions behind a
secondary surface. Preserve explicit gaps and provenance even when reducing
visual density.
